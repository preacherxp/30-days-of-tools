How the theme
switch works

The calendar's dark mode is three small ideas: colours as variables, a swap that happens in one frame, and a wall of mirror tiles that hides the swap. Every demo below runs the real code, slowed down so you can watch it. The button in the top right corner runs it at full speed.

Part 1

The theme is a set of variables

No rule on the page names a colour directly. Every background, border and text colour reads a CSS variable, and the variables have two sets of values. The light set lives on :root; the dark set overrides it whenever <html> has data-theme="dark".

:root {
  --bg: #f5f4f0;  --card: #ffffff;  --ink: #111111;  --line: #e3e1da;
}
[data-theme="dark"] {
  --bg: #181818;  --card: #1f1f1f;  --ink: #f5f4f0;  --line: #313131;
}
.cell { background: var(--card); border: 1px solid var(--line); }

So switching the theme is a single line of JavaScript, and the browser repaints every element with the other values in the next frame:

document.documentElement.dataset.theme = "dark";

One more piece runs before anything is drawn. A tiny script in <head> sets that attribute from your saved choice, or from your system setting the first time you visit. Without it, a dark mode visitor would see the light page flash on every load.

Part 2

The swap has to happen in one frame

Some elements animate their own colours: the cards fade their border over 300 milliseconds when you hover them. That's nice on hover and wrong during a theme switch. The background changes at once, the border fades slowly, and for a moment you see a light border on a dark card. Press the button to see both side by side, with the fade slowed to 1.2 seconds.

The fix is one rule. While <html> has the class theming, every transition on the page is switched off:

.theming *, .theming *::before, .theming *::after { transition: none !important; }

function swap() {
  root.classList.add("theming");           // fades off
  root.dataset.theme = next;               // every colour changes
  // two frames later the new colours are on screen; turn fades back on for hover
  requestAnimationFrame(() => requestAnimationFrame(() => root.classList.remove("theming")));
}

It waits two frames, not one, because the first requestAnimationFrame callback runs before the browser paints. Removing the class there would let the fades start anyway.

Part 3

The disco ball hides the swap

The transition never touches the page. A <canvas> is laid over the whole screen, tiles are drawn on it, and the theme flips underneath while the canvas covers everything. It runs in two phases of 560 milliseconds each:

  1. Cover. Tiles in the new theme's background colour spin in, starting at the button and sweeping outward, until they cover the screen.
  2. Swap. With the screen fully covered, swap() flips the theme. You can't see it happen.
  3. Reveal. The same tiles spin away in the same order, uncovering the page that is now in the new theme. Then the canvas is removed.

What each tile knows

When the transition starts, the screen is cut into a grid of 32 pixel tiles (24 in this miniature) and each tile draws its own random numbers once:

tiles.push({
  at:    d * 0.8 + Math.random() * 0.2,   // when it starts: distance from the button, plus noise
  spin:  ±(0.6 to 1.2) radians,           // how far it is turned while small
  shade: ±7%,                             // lighter or darker, like a facet catching light
  tint:  Math.random() < 0.06,            // flashes the red accent
  glint: Math.random() < 0.05,            // flashes white and draws a sparkle
});

d is the tile's distance from the button, divided by the distance to the farthest corner, so it runs from 0 next to the button to 1 in the far corner. The noise is why the wave front is ragged instead of a perfect circle. Turn on Colour tiles by when they start above to see at as a heat map.

One clock, a slice for each tile

Each phase has a clock t that runs from 0 to 1 over 560 milliseconds. Every tile moves during its own slice of that clock, 38% of the phase long, starting at a point set by at:

const TILE = 0.38;
const p = clamp((t - tile.at * (1 - TILE)) / TILE, 0, 1);   // this tile's own 0 → 1

A tile next to the button has at near 0, so it moves while t goes from 0 to 0.38. A tile in the far corner has at near 1 and moves from 0.62 to 1. The formula makes sure the last tile lands exactly when the phase ends, so the wall is always complete before the swap. The black line in the chart shows that: it reaches 100% right at swap().

Turning a number into a spinning mirror

p goes through an ease out curve, fast at first and gentle at the end, to give the size s. While covering, s goes from 0 to 1; while revealing, from 1 to 0. Everything about the tile follows from s and p:

const s     = coming ? easeOut(p) : 1 - easeOut(p);
const size  = (32 - 2) * s;              // the 2 pixels left over are the grout between mirrors
const angle = (1 - s) * tile.spin;       // most turned when smallest, square when it lands
const flash = Math.sin(p * Math.PI);     // 0 → 1 → 0: peaks halfway through the spin

if (s >= 1) ctx.fillRect(x, y, 33, 33);  // a landed tile is 1px bigger than the grid: no gaps left

flash drives every highlight: the red tint, the white glint and the four point sparkle all peak halfway through a tile's spin and fade as it lands. A tile at rest is drawn almost flat (a quarter of its shade), so the finished wall is an even colour. Landed tiles are drawn one pixel larger than their grid square, which closes the grout, so nothing of the old page shows through at the moment of the swap. Turn on X-ray and scrub across the middle of the slider to see the page change colour under a complete wall.

Part 4

Why the circle version broke

The first version used the browser's View Transitions API. The browser takes a picture of the page, flips the theme, takes a second picture, and stacks the new picture on the old one. The code then grew a circular hole in the new picture, clip-path: circle(), from the button outward.

To make it feel like a sphere, the new picture was also scaled from 106% down to 100% while the circle grew. That's the bug: inside the circle the page was slightly bigger than outside it, so every line of text and every card edge broke where the circle crossed it. Turn the scale on and drag the slider to see it.

circle radius 0 pxscale 1.000mismatch at the edge 0 px
A point at distance r from the button moves by r × (scale − 1) when scaled around the button. At the edge of the circle r is the radius, so a 600 pixel circle at 103% puts the inside 18 pixels out of line with the outside. The disco ball avoids the whole problem: there is only ever one real page, plus a cover that is either opaque or gone.
Part 5

Read the code

Everything lives in index.html, in this order:

<head> scriptPicks the theme before the first paint: your saved choice, or your system setting.
[data-theme="dark"]The dark values of every colour variable.
.themingSwitches all transitions off while the colours swap.
function disco()Builds the canvas and the tiles, runs both phases, calls swap() in the middle and removes the canvas at the end.
const PHASE, TILE560 ms per phase; each tile moves for 38% of it.
toggle click handlerSaves your choice, skips the animation if you prefer reduced motion, and ignores clicks while one is running.

To watch the real one slowly, change PHASE = 560 to 5600, open index.html in a browser and click the toggle.
